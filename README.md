# findyourcode

Поиск по коду **по смыслу**, а не по тексту.

```console
$ fyc find "где происходит авторизация пользователя"

 1. api/session.py:9-28  class CredentialChecker  [1.000]
     9 class CredentialChecker:
    10     """Validates the login/password pair a client presents at sign-in."""
    ...

 2. web/middleware.ts:8-20  function guard  [0.769]
     8 export async function guard(ctx: Context, next: () => Promise<void>) {
     9   const header = ctx.headers["authorization"] ?? "";
    ...
```

Ни слова «авторизация», ни слова `auth` в найденном коде нет — и это нормально.

## Как это работает

```
файлы → tree-sitter → семантические чанки → обогащение → эмбеддинги → SQLite
                                                                        ↓
                        запрос → эмбеддинг → вектора (sqlite-vec) ┐
                                              BM25 (FTS5) ────────┴→ слияние → выдача
```

Четыре решения, на которых держится качество:

1. **Границы чанков ставит парсер, а не счётчик байт.** Tree-sitter режет файл по
   функциям, методам и классам. Маленький класс — один чанк; большой — заголовок
   плюс отдельный чанк на метод; гигантская функция — окна с перехлёстом. Всё, что
   не попало в определения (импорты, константы, конфиг), собирается в блоки.
   Языки без грамматики и текстовые файлы уходят на построчный fallback, Markdown
   режется по заголовкам.

2. **Перед эмбеддингом чанк переписывается в человекочитаемый вид.** Идентификаторы
   разбираются на слова (`checkUserCredentials` → `check user credentials`),
   добавляются путь, breadcrumb класса, докстринг и краткое описание всего файла
   (модульный докстринг или комментарий-заголовок). Последнее часто решает: метод
   внутри `argparse.py` наследует «Command-line parsing library» — единственное
   место, где тема названа словами. Порядок полей не случаен: у моделей окно
   в 128–512 токенов, поэтому сначала идёт то, что важнее, сырой код — в конце.

3. **Поиск гибридный.** Вектор находит смысл, BM25 — точные имена (`retry_backoff`,
   `X-Request-Id`). Результаты сливаются: по умолчанию `blend` (min-max нормализация,
   0.75 семантике, 0.25 лексике, читаемый скор 0..1), опционально классический
   `rrf`. Кандидаты, пришедшие только из BM25, добираются точным косинусом.

4. **Индекс инкрементальный.** Файлы сравниваются по sha256, чанки — по хэшу текста,
   который уходит в модель. Правка одной функции переэмбеддит одну функцию:
   остальные чанки файла берут вектора из предыдущего поколения индекса.
   Откатили коммит — вектора найдутся в архиве, считать заново не придётся.

## Установка

```bash
pip install -e ".[all]"      # local-модель + sqlite-vec + pytest
pip install -e ".[local]"    # только оффлайн-режим
```

`sqlite-vec` не обязателен: без него вектора хранятся в обычной таблице, а KNN
считается numpy-перебором. До сотен тысяч чанков разница незаметна.

## Использование

```bash
fyc index                              # проиндексировать текущий проект
fyc index --reindex                    # перестроить с нуля
fyc find "отмена подписки и возврат денег"
fyc find "rate limit" --lang python --path src/api -n 20
fyc find "загрузка файлов в s3" --kind function --explain
fyc find "миграции схемы" --json | jq '.[0].path'
fyc status                             # что в индексе
fyc clear                              # удалить .findyourcode/
```

Полезные флаги `find`:

| Флаг | Что делает |
|---|---|
| `-n, --limit` | сколько результатов (по умолчанию 10) |
| `-L, --lines` | строк сниппета; `0` — весь чанк |
| `--lang / --path / --kind` | фильтры, можно повторять |
| `--mode hybrid\|semantic\|lexical` | отключить одну из веток поиска |
| `--fusion blend\|rrf` | как сливать два рейтинга |
| `--explain` | показать ранги и скоры каждой ветки |
| `--json` | машиночитаемый вывод |

## Модели

| Провайдер | Модель по умолчанию | Контекст | Комментарий |
|---|---|---|---|
| `local` | `paraphrase-multilingual-MiniLM-L12-v2` | 128 токенов | 220 МБ, оффлайн, 50+ языков запроса |
| `local` | `intfloat/multilingual-e5-large` | 512 токенов | 2.2 ГБ, заметно точнее, медленнее |
| `voyage` | `voyage-code-3` | 32k токенов | лучшее качество на коде, нужен `VOYAGE_API_KEY` |
| `openai` | `text-embedding-3-small` | 8k токенов | нужен `OPENAI_API_KEY`, работает и с совместимыми API |
| `hash` | — | — | детерминированный лексический fallback без зависимостей |

```bash
fyc index --model intfloat/multilingual-e5-large
fyc index --provider voyage
fyc providers
```

Индекс привязан к модели: сменили модель — `fyc index --reindex`, иначе инструмент
откажется мешать несовместимые векторные пространства.

## Конфигурация

`.findyourcode.toml` в корне проекта; любое поле переопределяется переменной
окружения `FYC_<ПОЛЕ>` или флагом CLI.

```toml
[findyourcode]
provider = "local"
model = ""
max_chunk_lines = 110      # больше — крупнее чанки, меньше — точнее адресация
overlap_lines = 12
alpha = 0.75               # вес семантики при слиянии
exclude = ["**/generated/**", "*.pb.go"]
include = []               # если непусто — индексируется только это
workers = 8
```

Список файлов берётся из `git ls-files -co --exclude-standard`, то есть `.gitignore`
соблюдается автоматически. Вне git-репозитория — обход директорий со встроенными
исключениями.

## Производительность и качество

Замер на CPython stdlib — 671 файл, 14 525 чанков, CPU, провайдер `local`:

| | |
|---|---|
| полная индексация | 329 с (~44 чанка/с, упирается в модель) |
| повторный `fyc index` без правок | 0.5 с |
| поиск | 2–4 с на холодном процессе (из них ~1.5 с — загрузка модели) |
| размер индекса | 72 МБ |

Для больших монорепозиториев: `--provider voyage` снимает нагрузку с CPU,
`workers` ускоряет парсинг, а кэш эмбеддингов делает переиндексацию после
`git pull` пропорциональной размеру диффа, а не репозитория.

Про качество честно. На том же корпусе запросы вроде «где происходит проверка
сертификата сервера» дают точное попадание первым результатом, а «разбор
параметров командной строки» поднимает `getopt` и `argparse` в топ-4, но первым
может встать похожий по смыслу, но не тот модуль. Потолок здесь — дефолтная
модель со 128-токенным окном: она видит имя, докстринг и описание модуля, но не
тело функции. Если качество важнее размера загрузки, берите
`intfloat/multilingual-e5-large` или `voyage-code-3` — конвейер от этого не
меняется, меняется одна строчка в конфиге.

## Языки

Python, JavaScript, TypeScript, TSX, Go, Rust, Java, Kotlin, Swift, Scala, Ruby,
PHP, C#, C, C++, Lua, Bash, Elixir и другие — через `tree-sitter-language-pack`.
Для незнакомых расширений работает построчный fallback.
